# 📜 版本更新历史 (Changelog)

本项目所有显著变更将记录于此文件。

## 0.1.20 — 2026-11-11

修复更换耗材后待办被自动打钩、但库存不扣减的问题。

### 修复
- **更换后库存不扣减**：读数恢复分支原本直接把「更换」待办置为已完成，绕过了唯一的更换入口 `async_mark_replaced()`，导致不记录更换时间、不重置计时、不扣减关联库存。现在该分支改走 `async_mark_replaced()`，与手动勾选待办完全一致。

### 变更
- **自动打钩改为「满值带」判定**：只有读数回到满量程 fresh 端（`REPLACE_CONFIRM_RATIO = 0.95`）才视为已更换——剩余寿命 ≥ 95%、已使用时长 ≤ 5% 阈值、剩余时间 ≥ 95% 寿命（需已配置寿命）。仅回到阈值上方的弱恢复不再打钩、也不扣库存，待办保持待处理等待人工确认。
- 数值阈值与自定义倒计时没有满值参考系，只能由手动勾选确认。
- 恢复确认从「触发差集驱动」改为「每轮全量扫描待处理更换待办」，修复「先弱恢复离场、之后才冲进满值带」时无法补确认的时序问题。

## 0.1.16 — 2026-09-04

首个公开版本：完整的家庭耗材生命周期管理体系——设备耗材状态监控、库存管理、更换待办、到期提醒通知与自动化服务。所有数据本地离线运行，不依赖任何云服务。

### 新增

**耗材类型监控**
- 5 个内置类型开箱即用：电池、净化设备滤芯、打印机耗材、扫地机耗材、净水器耗材。
- 自定义类型向导：类型键、名称、图标、默认阈值一站配齐，写入用户库，与内置类型平起平坐。
- 三种阈值类型（剩余寿命 %、剩余时间、已使用时长）× 三种计算方式（大于 / 小于 / 等于），单位支持 % / 分钟 / 小时 / 天；默认值三级兜底（条目 → 类型元数据 → 通用 20%）。
- 批量绑定：手动多选、正则动态入组（新增匹配实体自动加入）、`group.xxx` 群组展开且成员增减自动跟随。

**分组监控**
- 每个类型条目可建多个分组：绑定实体分组（多选 + 正则 + 群组辅助，提交取并集）与自定义耗材实体（自建倒计时数据，按已使用时长判定）。
- 分组可覆盖条目级阈值；每组独立生成诊断实体（更换状态）与数据传感器（组内最小值，纯数值）；自定义分组另有倒计时实体（`device_class: duration`）。

**库存管理**
- 库存台账：名称 / 关联类型 / 型号 / 单位 / 数量 / 阈值；常用耗材从库下拉选择自动带出。
- 勾选更换待办自动扣减库存；负数量 = 欠货，实体切换警示图标。
- 低库存告警并生成购买待办；库存状态诊断实体。

**待办联动**
- 基于 HA 原生待办平台：越阈生成「更换 XX」、低库存生成「购买 XX」；支持手机桌面小组件、日期设置、手动增删。

**通知推送**
- 双渠道（HA 持久化通知 + notify 通知实体）、双样式（人性化文案 / 状态值）、双模式（实时 / 每天固定时刻合并推送，默认 20:00）。
- 全局配置 + 条目级覆盖（含独立定时）；边沿触发，重启不轰炸。

**双库架构**
- 内置库随集成分发（`index.json` / `consumables.json` / `names.json`，中英双语）；用户库 `config/.consumable_manager/user_library.json`（原子写、可手改、同锚点用户优先）。
- 独立绑定层（HA Store）：实体 ↔ 耗材纯元数据映射，仅用于待办 / 通知显示规格。

**自动化服务（7 个）**
- `bind_entity`、`unbind_entity`、`query_binding`、`add_consumable`、`add_type`、`query_data`、`adjust_stock`——表单由 services.yaml 驱动，配置界面与自动化 / 脚本双入口；`query_data` 为仅响应服务，支持 5 种数据类型。

**贡献流水线**
- 用户库 PR 到 main 分支的 `contributions/<用户名>/`；GitHub Actions 自动校验（代码 / 标识字段强制 ASCII）、锚点去重、多语言拆解并组装进内置库。

**兼容版本**
- Home Assistant 2026.1+；品牌图标显示建议 2026.3+。
